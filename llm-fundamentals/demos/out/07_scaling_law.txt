Chinchilla 最优配比：D_opt ≈ 20 * N（参数量 -> 训练 token 数）
模型                     参数量 N      最优 token 数 D       训练算力 C≈6ND(FLOPs)
GPT-2                     2B              0.0T                2.70e+20
LLaMA-7B                  7B              0.1T                5.88e+21
LLaMA-13B                13B              0.3T                2.03e+22
LLaMA-70B                70B              1.4T                5.88e+23
GPT-3-175B              175B              3.5T                3.67e+24

  现实对照：LLaMA-7B 实际训练了 1T tokens（≈20x 参数量，基本符合 Chinchilla）
  GPT-3 175B 只训了 300B tokens（≈1.7x 参数量）—— Chinchilla 认为它数据严重不足

幂律关系：损失随规模下降（Kaplan 形式 L = (N_c / N)^alpha）
参数量                  预测 loss       相对 0.1B 的下降
       0.1B        2.8300              0.0%  #############################################
       1.0B        2.3756            -16.1%  ##################################
      10.0B        1.9943            -29.5%  ########################
     100.0B        1.6741            -40.8%  ################
    1000.0B        1.4053            -50.3%  ##########

  注意：这是「其它条件不变」下的趋势。真正在意的是「同样算力下怎么分配 N 和 D」

同样的算力预算，参数和数据怎么分？（Chinchilla 的答案是：平分给两边）
  算力预算 C = 1.00e+23 FLOPs，C = 6ND 且 D = 20N -> N = sqrt(C/120)
  -> 最优参数量 N ≈ 28.9B，最优数据量 D ≈ 0.58T tokens
  若把参数堆到 2x（57.7B）却只喂同样的数据，loss 会变差 —— 这就是参数过剩

  现代实践：推理成本也要算进账 -> 大家普遍训得比 Chinchilla 最优更久（overtrained）
  （LLaMA-3 8B 训了 15T tokens，远超 20x8B=160B，因为小模型推理便宜、总拥有成本更低）
