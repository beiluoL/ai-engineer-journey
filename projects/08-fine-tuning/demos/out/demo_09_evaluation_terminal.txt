  但先别急着下结论 —— 上面这个指标被「记忆」主导了：
    基座在预训练**见过**的语料上困惑度是 148.2，而在**没见过**的通用文本上是 742.6
    （差 5.0 倍）。预训练只跑了 120 步，这个差距说明基座
    对通用语料的低困惑度主要来自**记忆**而不是泛化，任何微调都会打散它。

  换个更公允的判据 —— 看**没见过**的通用语料（真正的泛化）：
  未见通用语料困惑度  微调前    微调后    变化       判定
  ---------  -----  -----  -------  --
  LoRA r=8   742.6  586.1  -21.08%  变好
  全量微调       742.6  535.6  -27.88%  变好
  两者在未见通用语料上**都变好了** —— 因为 Java 答案本身也是中文技术文本，
  等于又给这个欠训练的基座喂了通用语料。

  ⚠ 一个**推翻常识**的实测结果（值得写进文档）：
    教科书常说「LoRA 比全量微调更抗遗忘」。本次实测相反 ——
    在预训练语料上，LoRA 涨 +241%，全量只涨 +119%。
    原因不是 LoRA 本身有问题，而是：① 基座本来就欠训练，
    ② LoRA 的等效 ΔW 幅度并不小 —— 本 demo 实测 mean|ΔW|/mean|W| = 104.1%，
       而全量微调每步只挪动一点点，反而整体偏移更小。
    结论：「LoRA 更抗遗忘」的前提是**基座本身泛化良好**，不能无条件相信。

  真正值得记住的是**判据的形式**：域内必须降、通用不能涨、两者要同时看。

── 7. 定性对比：同一道题，微调前后各生成一段 ────────────────────────────────────────────────────
  prompt: '### 指令:\n请解释 Java 中 HashMap 的底层原理（以 JDK 8 为例）\n\n### 回答:\n'

  【基座（未微调）】
    '### 指令:\n请解释 Java 中 HashMap 的底层原理（以 JDK 8 为例）\n\n### 回答:\n如  \n词er。次mtr维\n连 根 ，x m  度先。E模型token否四意l 留odw？edm'
  【LoRA 微调后】
    '### 指令:\n请解释 Java 中 HashMap 的底层原理（以 JDK 8 为例）\n\n### 回答:\n相与  ，变量步选新数组，'
  【参考答案（数据集里的 output）】
    JDK 8 的 HashMap 底层是「数组 + 链表 + 红黑树」。数组的每个槽位称为桶（bucket），通过 key 的 hashCode 经过扰动函数再与…

  如实呈现：两段生成都是**乱码级别**的。这不是 bug —— d_model=64、2 层、
  预训练语料只有 1KB 量级，模型根本没有能力生成连贯中文。
  但它确实学会了「答案区的 token 分布」：困惑度从几万降到几百是真的。
  结论：**困惑度下降是必要条件，不是充分条件**；定性评测必须单独做。
