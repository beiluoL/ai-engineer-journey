
==============================================================================
  M01 · Fine-Tuning：全量微调 vs LoRA
==============================================================================
  叙事：让「通用但弱」的基座模型，变成「Java 面试」领域的模型。
  本 demo 只回答一件事：两种微调方式，动手的代价差多少。

── 1. 基座模型（复用 P06 手写的 Decoder-Only Transformer） ──────────────────────────────
  加载耗时                                   0.03 s
  基座来源                                   cache（从 models/ 缓存读取）
  缓存文件                                   base_lm.npz（1810 KB，预训练 120 步）   预训练 loss 6.948 → 4.715
  词表大小 / d_model / 层数                    1024 / 64 / 2
  基座参数量（P08 口径）                          230,656
  基座参数量（P06 parameters() 口径）             165,120   ⚠ 少了一整个词嵌入
  两者的差                                   65,536   = TokenEmbedding 未继承 Module，被 _collect_params 漏掉

── 2. 参数账：要训练多少个数字 ───────────────────────────────────────────────────────────
  方式        可训练参数    基座参数(冻结)  可训练占比    每个任务的存储(fp32)
  --------  -------  --------  -------  -------------
  全量微调      230,656         0  100.00%      901.00 KB
  LoRA r=8   27,136   230,656   10.53%      106.00 KB
  可训练参数量倍数                               8.50×   全量 / LoRA
  LoRA 注入层数                              13 个线性层
  · decoder.blocks.0.attn.Wq
  · decoder.blocks.0.attn.Wk
  · decoder.blocks.0.attn.Wv
  · decoder.blocks.0.attn.Wo
  · …

── 3. 训练显存账（参数 + 梯度 + 优化器状态） ─────────────────────────────────────────────────
  训练时每个**可训练**参数要占：4B(参数) + 4B(梯度) + 8B(Adam 的 m 与 v) = 16B。
  被冻结的基座只需要躺着，4B/参数，不产生梯度和动量。
  方式        权重           梯度         Adam 状态    合计       相对全量 
  --------  -----------  ---------  ---------  -------  -----
  全量微调        901.00 KB  901.00 KB    1.76 MB  3.52 MB  1.00×
  LoRA r=8  1,007.00 KB  106.00 KB  212.00 KB  1.29 MB  0.37×
  训练显存节省                                 2.72×   （权重那部分省不掉，省的是梯度+动量）

── 4. 真跑一遍：各训 60 步（同一份 Java 面试数据，只算答案区 loss） ─────────────────────────────────
  全量微调 首步 loss                           8.2909
  全量微调 末步 loss                           6.1109
  全量微调 下降                                2.1800
  全量微调 耗时                                3.34 s
  LoRA 首步 loss                           8.2909
  LoRA 末步 loss                           6.1882
  LoRA 下降                                2.1028
  LoRA 耗时                                3.47 s

  loss 曲线采样（每 10 步）：
           全量微调    LoRA r=8
  -------  ------  --------
  step 1   8.2909    8.2909
  step 11  6.6401    6.6785
  step 21  6.3540    6.4202
  step 31  6.1918    6.1631
  step 41  6.1191    6.1681
  step 51  5.9035    5.9488
  step 60  6.1109    6.1882

── 5. 本 demo 的关键数字 ───────────────────────────────────────────────────────────
  可训练参数（占基座）                             LoRA 27,136 / 全量 230,656 = 11.76%
  可训练参数（占注入后总量）                          27,136 / 257,792 = 10.53%
  训练显存（含 Adam）                           1.29 MB vs 3.52 MB = 36.76%
  60 步后 loss                             全量 6.1109 / LoRA 6.1882
  60 步后谁更低                               全量微调（差 0.0772）

  读法：LoRA 只动了约 1/8.5 的参数，loss 却追平（甚至略优于）全量微调 ——
  这正是「低秩假设」的实证：本任务的适配方向，确实躺在很低维的子空间里。
  注意 loss 只是训练目标：全量微调改写的是整个基座，代价要到 M09 的
  「灾难性遗忘」检查里才看得出来 —— 只看 loss 会得出错误结论。
