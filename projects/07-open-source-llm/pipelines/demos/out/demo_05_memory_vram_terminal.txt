== demo_05_memory_vram：权重与 KV Cache 显存账本 -------------------------------

数据来源：pipelines/data/open_models_weights.json（状态 all_ok）

== 换算口径 ----------------------------------------------------------------
  dtype  字节/参数
  -----  -----
  fp32   4.0  
  fp16   2.0  
  bf16   2.0  
  int8   1.0  
  int4   0.5  
   公式：权重 GiB = 参数量 × 字节/参数 ÷ 1024³
   公式：KV Cache/token = 2(K,V) × 层数 × kv_heads × head_dim × 字节/参数

== 表 1：同一模型在不同精度下的权重大小（GiB） --------------------------------------------
  模型                     标称    手算(B)  fp16   int8  int4
  ---------------------  ----  -----  -----  ----  ----
  Qwen2.5-0.5B-Instruct  0.5B  0.49   0.92   0.46  0.23
  Qwen2.5-1.5B-Instruct  1.5B  1.54   2.88   1.44  0.72
  Qwen2.5-7B-Instruct    7B    7.62   14.18  7.09  3.55

   以 Qwen2.5-7B-Instruct 为例：
      fp32 权重 =  28.37 GiB
      bf16 权重 =  14.18 GiB
      int8 权重 =   7.09 GiB
      int4 权重 =   3.55 GiB
   -> bf16 → int4 把 14.18 GiB 压到 3.55 GiB，降为 1/4。

== 表 2：KV Cache（bf16，batch=1）随上下文长度增长 ----------------------------------
  模型                     层数  KV头  字节/token  2K tokens  8K tokens  32K tokens
  ---------------------  --  ---  --------  ---------  ---------  ----------
  Qwen2.5-0.5B-Instruct  24  2    12288.0   0.02       0.09       0.38      
  Qwen2.5-1.5B-Instruct  28  2    28672.0   0.05       0.22       0.88      
  Qwen2.5-7B-Instruct    28  4    57344.0   0.11       0.44       1.75      

== 关键对照：KV Cache 会不会追上权重？ ----------------------------------------------
   Qwen2.5-0.5B-Instruct
     权重(bf16)        =   0.92 GiB
     KV/token          =  12288 B
     seq=  2048 -> KV =   0.02 GiB   (KV/权重 =   2.5%)
     seq=  8192 -> KV =   0.09 GiB   (KV/权重 =  10.2%)
     seq= 32768 -> KV =   0.38 GiB   (KV/权重 =  40.8%)
     -> 首次超过权重的序列长度：在测试范围内未超过

   Qwen2.5-1.5B-Instruct
     权重(bf16)        =   2.88 GiB
     KV/token          =  28672 B
     seq=  2048 -> KV =   0.05 GiB   (KV/权重 =   1.9%)
     seq=  8192 -> KV =   0.22 GiB   (KV/权重 =   7.6%)
     seq= 32768 -> KV =   0.88 GiB   (KV/权重 =  30.4%)
     -> 首次超过权重的序列长度：在测试范围内未超过

   Qwen2.5-7B-Instruct
     权重(bf16)        =  14.18 GiB
     KV/token          =  57344 B
     seq=  2048 -> KV =   0.11 GiB   (KV/权重 =   0.8%)
     seq=  8192 -> KV =   0.44 GiB   (KV/权重 =   3.1%)
     seq= 32768 -> KV =   1.75 GiB   (KV/权重 =  12.3%)
     -> 首次超过权重的序列长度：在测试范围内未超过

== 两个结论 ----------------------------------------------------------------
   1. 量化权重 ≠ 解决长上下文。KV Cache 独立按 上下文长度 × batch 线性增长，
      要压它得单独量化 KV（或用 GQA/MLA 这类结构上就省 KV 的架构）。
   2. GQA 的价值在这里变现：表里 KV 头数远小于注意力头数，
      同样算力下能撑的上下文长度直接翻倍。
