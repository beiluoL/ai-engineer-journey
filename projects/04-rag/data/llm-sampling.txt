LLM 采样参数：temperature / top_p / penalty
===========================================

生成模型每次只输出一个 token，然后把它的概率分布按「采样策略」抽一个出来。
所以所谓"回答random"其实是采样策略决定的。

temperature（温度）
-------------------
对 logits 做除法后再 softmax：

    P(token) = exp(logit / T) / Σ exp(logit_j / T)

T 小（如 0.1）→ 分布被压尖，几乎必选最高概率词，输出接近贪心解码，确定性高；
T 大（如 1.5）→ 分布被摊平，低概率词也有机会，输出更发散、更容易跑题。

经验取值：
    抽取 / 分类 / 代码补全   T = 0 ~ 0.2
    日常对话                 T = 0.7 ~ 0.8
    创意写作 / 头脑风暴      T = 1.0 ~ 1.2

top_p（核采样）
---------------
只保留累积概率达到 p 的最高若干 token，再在这少数候选里采样。
常和 temperature 一起用；同时调两个参数会让效果难以预测，建议二选一为主。

    代码生成常用 top_p = 0.9 ~ 0.95

repetition_penalty / frequency_penalty
--------------------------------------
对已经出现过的词做惩罚，用来压 repetition loop：

    repetition_penalty = 1.0   不惩罚（默认）
    presence_penalty   > 0     出现过的词降权
    frequency_penalty  > 0     出现得越多降权越强

常见坑
------
1. temperature=0 不等于"完全确定"：服务端可能有采样开关、批处理共享 GPU 内核，
   同样输入两次不完全一致。要可复现就固定 seed，或走 greedy 接口。
2. -temperature 调很高就别指望事实准确：事实类问答应该 T=0，发散只留给写作。
3. 长文本生成把 T 调低：温度越高，越容易在后半段开始胡言乱语。
4. 采样参数和 prompt 是协同的：prompt 已经写得很明确时，T 再高也帮助有限。
