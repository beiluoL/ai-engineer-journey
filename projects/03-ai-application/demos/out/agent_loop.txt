===== 1. 发给模型的工具清单（JSON Schema）=====
  add        计算两个数的和。用于演示工具调用。
             参数: ['a', 'b']
  multiply   计算两个数的乘积。
             参数: ['a', 'b']
  get_weather 查询指定城市今天的天气（演示用：返回固定数据，不联网）。
             参数: ['city']

===== 2. 本地执行：模型说要调，其实是你自己在算 =====
  dispatch(add, {'a': 3, 'b': 4}) → {'result': 7}
  dispatch(multiply, {'a': 6, 'b': 7}) → {'result': 42}
  dispatch(get_weather, {'city': '深圳'}) → {'result': {'city': '深圳', 'temp_c': 26, 'desc': '晴', 'source': 'demo'}}
  dispatch(不存在, ...) → {'error': "没有名为 'no_such_tool' 的工具，可用工具: ['add', 'get_weather', 'multiply']"}
  → 工具出错也要作为 {'error': ...} 返回，让模型自己纠正，而不是崩掉

===== 3. 完整两轮循环：tool_calls → 执行 → 回灌 → 最终回答 =====
  最终回答: 3 + 4 = 7
  轨迹共 4 条：
    [0] user      '3 加 4 等于几？'
    [1] assistant ''  tool_calls=['add']
    [2] tool      '{"result": 7}'  tool_call_id=call_1
    [3] assistant '3 + 4 = 7'
  → 少了第 4 步（role=tool 回灌），模型就会凭空编一个结果

===== 4. 一轮就答完的情况（不需要工具）=====
  最终回答: 深圳今天晴。 ｜轨迹条数: 2 （没有调用过工具）

===== 5. 一直要调工具 → 轮数上限抛错，不死循环 =====
  ToolLoopError: 工具调用轮数达到上限 4，仍未产出最终回答
  → 必须有上限：模型陷入循环时，没有上限就是无限烧钱
