# 第二轮：架构设计

## 面试官 Q2

请你画一下整个系统架构，并说明一次用户请求的完整链路。

你需要讲：

```text
用户
 ↓
Spring Boot
 ↓
Agent
 ↓
Tool Calling
 ↓
RAG
 ↓
Milvus
 ↓
Prompt
 ↓
Qwen LoRA
 ↓
返回
```

---

标准回答：

> 用户请求首先进入 Spring Boot 接口层，接口将请求交给 LangChain4j Agent。Agent 根据用户意图判断是否需要调用工具，如果涉及技术知识查询，则调用知识库检索 Tool。Retriever 将用户问题转换成 Embedding，在 Milvus 中进行向量搜索，返回相关文档片段。系统将用户问题、历史上下文以及检索结果组合成 Prompt，然后发送给 Qwen 模型。Qwen 结合 LoRA 微调后的面试回答能力生成最终结果，通过 SSE 流式返回给前端。

# 第三轮：RAG 深挖

## 面试官 Q3

为什么你的项目需要 RAG？

为什么不能直接把 Java 知识全部微调进去？

---

考察：

你是否理解：

RAG vs Fine-tuning。

标准回答：

> 因为两者解决的问题不同。微调主要用于改变模型行为，例如让模型按照 Java 高级面试方式回答；RAG主要解决外部知识注入问题，例如公司内部文档、源码分析和项目资料。如果把所有知识通过微调注入，会存在训练成本高、知识更新困难以及模型遗忘问题，所以企业应用通常采用 RAG 管理动态知识。

---

# 第四轮：RAG链路追问

## 面试官 Q4

你的 RAG 从上传文档到回答，中间经历哪些步骤？

必须说：

```
Document Loader
 ↓
Text Splitter
 ↓
Embedding
 ↓
Vector Store
 ↓
Retriever
 ↓
Prompt
 ↓
LLM
```

标准回答：

> 用户上传文档后，系统首先通过 Document Loader 解析文件，然后使用 Text Splitter 进行 Chunk 切分。每个 Chunk 通过 Embedding 模型转换成向量，并存储到 Milvus 向量数据库。当用户提问时，系统将问题向量化，通过相似度搜索召回 TopK 文档片段，再将这些上下文和用户问题组合成 Prompt，发送给大模型生成答案。

---

# 第五轮：Chunk追问（高频）

## 面试官 Q5

为什么 RAG 需要 Chunk？

为什么不能直接把整个 PDF 放进去？

标准：

> 大模型存在上下文窗口限制，同时长文本直接输入会导致重要信息被稀释。因此需要将文档切分成合理大小的 Chunk，使每个片段语义完整，并通过向量检索快速定位相关内容。

继续追问：

## 那 Chunk 多大？

回答：

> 没有固定值，需要根据场景调整。通常会结合模型上下文长度、文档类型和检索效果测试，例如几百到上千 Token，并设置一定 overlap 保证上下文连续性。

---

# 第六轮：Embedding追问

## 面试官 Q6

Embedding到底是什么？

为什么文本可以搜索？

标准：

> Embedding 是将文本转换为高维向量表示的过程。语义相近的文本在向量空间距离更近，因此可以通过向量相似度计算找到相关内容。例如用户问“HashMap线程安全吗”，系统可以检索到“ConcurrentHashMap并发控制机制”等语义相关文档。

---

# 第七轮：LoRA深挖

## 面试官 Q7

为什么你的项目需要 LoRA 微调？

标准：

> 我的场景不是让模型学习全部 Java 知识，而是希望模型形成稳定的面试回答风格，例如先给结论，再分析源码，再结合项目。因此使用 LoRA 对模型行为进行领域适配，同时知识内容通过 RAG 动态提供。

---

# 第八轮：LoRA原理

## 面试官 Q8

LoRA具体怎么实现？

不要只说：

❌

> 加一个插件。

标准：

> LoRA是一种参数高效微调方法。传统微调需要更新模型大量参数，而LoRA冻结原模型参数，在部分 Transformer 权重旁增加低秩矩阵，只训练这些新增参数。训练完成后可以将 Adapter 和基础模型合并，或者推理时动态加载。

---

# 第九轮：Agent追问

## 面试官 Q9

你的 Agent 和普通 Chat 有什么区别？

标准：

> 普通 Chat 主要是用户输入后模型直接生成回答，而 Agent 增加了任务规划和工具调用能力。Agent 会根据用户意图判断是否需要调用外部工具，例如查询知识库、分析简历，然后根据工具结果继续推理生成答案。

---

# 第十轮：Tool Calling追问

## 面试官 Q10

Tool Calling整个流程是什么？

这是你的重点。

标准：

> 用户请求进入系统后，Java 应用将工具定义的 Schema 和用户消息一起发送给模型。模型根据描述判断是否需要调用工具，如果需要，会返回结构化 Tool Call，包括工具名称和参数。Java 应用收到后进行参数校验，然后执行真实业务方法，将结果作为 Tool Result 返回给模型，模型结合结果生成最终自然语言回答。

链路：

```text
User

↓

Java

↓

LLM + Tool Schema

↓

Tool Call

↓

Java执行Tool

↓

Tool Result

↓

LLM

↓

Answer
```

推荐：

---

## 难点1：RAG效果优化

回答：

> 初期检索存在召回不准确的问题，通过优化 Chunk 策略、调整 Embedding 模型、增加 Metadata过滤提升效果。

回答：

> Agent存在工具选择错误问题，通过明确 Tool 描述、限制工具权限以及增加参数校验提升稳定性。

## 难点3：模型输出控制

回答：

> 通过 Prompt 约束、LoRA 微调和 Evaluation 数据集持续优化回答质量。

# 第十二轮：面试官终极追问

## Q12

如果用户问的问题知识库没有怎么办？

标准：

> 首先通过检索结果置信度判断，如果没有达到阈值，则降低知识库内容权重，并提示模型基于已有能力回答，同时明确说明不确定性。生产环境可以增加拒答机制，减少幻觉。
