项目目标

← 上一节文档开头下一节 →为什么做这个项目

掌握模型微调，让通用模型变成领域模型。

为什么做这个项目

← 上一节项目目标下一节 →解决什么问题

RAG 是外挂知识，Fine-tuning【微调】是把知识和行为"烧进"模型。生产中 LoRA / QLoRA 是标配。

解决什么问题

← 上一节为什么做这个项目下一节 →最终能力
  • RAG 能加知识但不能改变模型行为
  • 需要模型在特定领域表现更好
  • 需要让模型学会新的任务格式

三个"想当然被实测推翻"的结论

  • "LoRA 更抗遗忘"在本项目不成立：通用（见过）语料上 LoRA 涨 +240.71%，全量微调只涨 +118.83%。 原因是基座本身欠训练，且 LoRA 等效 mean|ΔW|/mean|W| 已到 104.1%，并不"小改动"。
  • 小模型上 QLoRA 不划算：adapter 106 KB 反而大于 NF4 量化后的基座 82.54 KB（128.42%）。 量化收益随模型规模线性增长——7B 上才是 0.66 MB vs 3.5 GB 的区别（外推，非本机实测）。
  • 困惑度下降 ≠ 可用：域内困惑度 3649.9 → 421.1 是真的，但玩具模型生成出来仍是乱码。 指标是真的，能力不是。

顺带挖出的 P06 缺陷（本项目不改 P06，照实记录）

  • Module.parameters() 漏掉整个词嵌入（TokenEmbedding 未继承 Module），65,536 参数不在表内。
  • Adam 动量从未累积：step() 里 m/v 是局部变量、没写回 self.state，训完非零元素 0/54,272。
  • Tensor._prev 是 set，迭代顺序由对象地址决定 → 跨进程不可复现。本项目用 enable_deterministic_autograd() 在不改 P06 的前提下包一层修掉。
